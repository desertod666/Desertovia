# PKG-T020: перенос и подтверждённость себестоимости

Реализация в `feat/desertovia-1-0-economy`, поверх M1 `bc9bd81`.
Основание — прямой ответ владельца PKG-D108 в [D-105](DECISIONS.md).
Результаты проверок и граница выпуска отдельно фиксируются в progress JSON.

При старте частного крафта фактически списанная стоимость входов сохраняется
в Citizen.CycleInputCostBasis вместе с признаком подтверждённости. Завершение
не восстанавливает её по оставшемуся инвентарю. Загрузка БД, медицинская пауза
и ожидание безопасного отдыха сохраняют это обязательство.

`ProductionCost.Allocate` делит общую стоимость пропорционально количеству
реальных продуктов и их базовым ценам EconomyRules. Целые минимальные единицы,
Int128 для промежуточного умножения, метод наибольших остатков; равные остатки
разрешаются порядком ResourceKind. Перестановка выходов не меняет результат.
Стоимость потерянного при переполнении выхода не повышает стоимость оставшегося.
Случайный боевой лут не становится получателем стоимости рецепта.

`CostBasisKnown=false` означает непроверенную историю, а не бесплатно добытую
вещь. Маркер сохраняется через дробление, передачу, личный склад, резерв лота
и отмену. Смешанная партия консервативно остаётся непроверенной целиком; её
известная числовая часть стоимости не удаляется. Старый JSON без маркера,
старые открытые лоты и незавершённые циклы не получают фиктивную известную
нулевую стоимость. Отдельная будущая сверка ledger может подтвердить их историю.

Продажа непроверенной партии не увеличивает ProfitToday; покупатель получает
подтверждённую стоимость реально уплаченной суммы. Это подготовка T024,
не включение настоящего налога: существующий TaxEnabled остаётся false.
Деньги не конвертируются, суммы старой CostBasis не переписываются.

Частный монастырский обмен переносит стоимость и маркер обоих входов в Remedy.
Возврат стройматериалов без полной истории инвестиций остаётся непроверенным,
вместо объявления нулевой подтверждённой стоимости. Полный учёт капитала
строений, себестоимость посева/удобрения и натуральная оплата дополняются
контрактами T021/F001–006; текущий срез не объявляет их завершёнными.

Миграция ProductionCostBasis добавляет три скалярных поля и метаданные в
существующий JSON. Удаления имущества/запросов/денег нет. При откате нужен
штатный backup/restore; уже накопленную новую историю нельзя считать сохранённой
после удаления новых полей старым кодом. Публичная база не мигрировалась.

Проверено 558 Domain, включая крафт после сериализации, неизвестный legacy JSON,
личный склад и сохранение стоимости до long.MaxValue. Frontend build/lint проходят.
Четыре новых API-сценария прошли после исправления enum-converter в тестах;
15 существующих экономических API тоже прошли. 22 browser-сценария плюс8
финальных проверок44×44 подсказок прошли. Полный CI нового дерева ещё нужен.
