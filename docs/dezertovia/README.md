## Как сохранять память, а не надеяться на историю чата

- В начале работы читать корневой AGENTS.md, этот индекс и DECISIONS.md.
  Найти строку нужного DZ-ID в матрице, прочитать реальные функции по указанным путям.
- Для каждого изменения фиксировать: ID правила, источник/commit, причина,
  затронутые слои, миграция, проверки, состояние `planned / implemented / verified / released`.
  Эти состояния различать: наличие кода не доказывает выкладку или исправление на телефоне.
- После нового решения сначала обновлять DECISIONS.md и зависимые строки документов.
  Последнее явное решение владельца выше старых TODO и рекомендаций зрителей.
- После обновления от автора сравнить базовый SHA, diff и затронутые DZ-ID;
  не заменять документацию его roadmap и не перезаписывать нашу ветку зеркалированием.
- Перед выпуском проверить progress.json, матрицу, отменённые пункты, сохранность
  данных и реальные результаты тестов. Закрытый сервер не проверять по имени версии в коде.
- Каждый законченный этап сохранять коммитом в своём репозитории. Скриншоты,
  секреты, базы и сырые отзывы не служат технической памятью и не попадают в git.
