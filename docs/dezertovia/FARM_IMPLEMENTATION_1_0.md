## Узкий допуск F001/F002

FarmerAdmissionEnabled — явный переход прав работы на общих грядках. По
умолчанию false для совместимости, владелец включает его явно; автоматической
смены правил/назначений при миграции нет. Это ещё не переключатель готовой
экономики урожая90/10. Полный договор и расчёт F004 должны быть доведены отдельно.

| Действие | Царь | Посадник с CanManageFarm | Остальные |
| --- | --- | --- | --- |
| Включить ограничение общих грядок назначенными фермерами | Да | Нет | Нет |
| Назначить/снять IsFarmer | Да | Да | Нет |
| Выдать CanManageFarm действующему посаднику | Да | Нет | Нет |
| Работать на общей грядке после включения допуска | Только действующим героем с IsFarmer | Только с IsFarmer | Только с IsFarmer |
| Работать на сохранённой своей личной ферме | По прежним правилам | По прежним правилам | По прежним правилам |

Посадничество само по себе не даёт фермерского управления. Снятие посадника
сбрасывает CanManageFarm. Назначение не даёт иных политических прав, не меняет
профессию/навыки/владение. Новый запрос после снятия допуска запрещён; принятая
работа завершается по сохранённым условиям. Новые tend-fields после перехода
запрещены, чтобы не оставлять абстрактный обход ручного выращивания.

PUT farm/admission и citizens/{id}/farm-access используют RequestId и
EconomyReceipt с actor/payload fingerprint, существующую транзакцию и PG-lock
мира. Повтор старого назначения не отменяет более позднее снятие; тот же id с
другими условиями отклоняется. Цель и управляющий проверяются внутри того же мира.
Событие назначения публикуется после commit. Миграция44 FarmerAdmission добавляет
три bool c false по умолчанию; посевы, деньги, прогресс и личные фермы не преобразует.

В интерфейсе царя появились допуск фермера, отдельное поручение посаднику и явное
включение ограничения. Управляющий видит только фермерское назначение; на общей
ферме неназначенный житель может осмотреть участок и получает объяснение запрета.
Сервер остаётся источником прав, скрытие кнопок не заменяет проверки API.

## Вклад и фонд

Приняты владельцем40/30/10/20: посадка/все нужные поливы/удобрение/сбор. Если
этап не происходил, нормируются остальные; несколько поливов делят30. Повтор
одного принятого труда не добавляет веса. FarmContributionRules.Allocate использует
точные рациональные веса и детерминированный остаток, сохраняя весь заданный фонд
даже для1 дробной единицы или long.MaxValue. Дробная единица —1/1_000_000;
это точность учёта права, а не дополнительная физическая Food.

Участники и фактический итог теперь сохраняются по правилам ниже. **Выдача90/10
и денежного фонда ещё не подключена.** История не является финансовым требованием.

Владелец выбрал: **до фактического сбора денег нет**. Погибший до сбора посев
не создаёт продукты или зарплату; неиспользованный обеспеченный фонд возвращается.
История труда остаётся. При сборе — один обеспеченный фонд и сразу защищённые10%
реальной Food,90% общине; зерно/лён общие. Реальные складские потери уменьшают
оба запаса пропорционально. Claim не дублирует еду и не обходит вместимость склада.

## Сохранённая история F003

У новых общих посевов после включения допуска ContributionVersion1. Версия
принятой работы хранится в Citizen.CycleFarmContributionVersion: новый режим
не переписывает начатый старый цикл. FieldBed содержит SownAt и участников;
FarmCrops — долговечную запись на GenerationId. Записываются только завершённые
полезные действия; дождь/лишний клик/отмена не добавляют вклада. Удобрение ещё
не реализовано и не создаёт фиктивный этап.

FarmCrops связан с миром, без FK на Citizen: уход участника или удаление грядки
не стирает историю. При сборе однократно фиксируются участники, фактический
выход/потери и существующий factor сборщика. Запись происходит в той же транзакции.
Версия1 относится к истории, не обещает ещё не реализованную выдачу Food/денег.

При задержанном расчёте новые работы версии1 завершают уход по CycleEndsAt:
посев успевает расти офлайн, поздний полив не дарит свежие30 минут при входе.
Старые работы/посевы версии0 и личные фермы сохраняют прежние правила.
Миграция45 FarmContributionHistory добавляет таблицу и default0 версии цикла;
старый JSON без истории/с NULL-коллекцией читается как неизвестная история.

GET farm/history ограничен20 записями, plotId и курсором внутри мира. Lost
означает отсутствие поколения на текущем поле; повреждённое здание с сохранённым
растением автоматически не уничтожает посев. Денежное закрытие утраты — ещё F004.
В UI сворачиваемые «Кто помогал»/«История посевов», исполнитель, дождь и причина
занятости. Новые общие команды/повтор открывают конкретную ферму с инструментом/
семенами, не отправляя неявную работу. У старого сервера без метаданных остаётся
прежний fallback. Это проверено на реальной композиции карты отдельно от стенда.

Для F004 защитить резерв **до** питания в CycleEngine.Finish: урожай1 нельзя
целиком съесть до обеспечения доли. Проверить raw Goods в buy-stock/рецептах/
выдаче: claim не вторая Food. Продолжить существующий WorkOrder для полного
урожая: не завершать его как неполезный сразу после посева и не отменять фонд
растущего общего растения при уходе сеявшего. Оплата только после сбора;
утрата возвращает фонд. Версию вознаграждений хранить отдельно от версии
истории1, без ретроактивных обещаний старым посевам. Это условия следующей
реализации, текущий код по ним продукты/деньги не выдаёт.

## Осмотр, прогноз и узкий экран F005

Царь, наблюдатель и житель в безопасном отдыхе используют тот же пространственный
вид грядок в WatchPopup, без рабочих инструментов и фиктивного Citizen. Нажатие
не будит героя, не создаёт цикл и не отправляет рабочую команду. Старый сервер
без GenerationId сохраняет FieldsCard. История раскрывается по требованию.

FarmRules.MaturityWindow считает диапазон из текущего реального GrowthOf:
минимум при постоянной влажности, максимум при уже внесённой воде и последующей
сухой почве. Будущая случайная погода не раскрывается. Прогноз не изменяет растение.
UI отдельно указывает базовый урожай до навыков/потерь; это не финансовое обещание.
На ПК окно фермы получает до600px высоты в пределах экрана, чтобы описание выбранной
грядки не исчезало за обрезанной картой. На телефоне остаётся ограниченная по высоте
карточка с внутренней прокруткой. Прогноз и история помощи сворачиваются.

Проверка настоящего телефонного вида выявила неточность миникарты: координаты
должны считаться по canvas с изображением, исключая рамку. Minimap.pick и
проверка реального нажатия теперь используют границы этого canvas. После правки
осмотр фермы с карты прошёл на ПК и телефоне при сохранённом Resting и нуле
запросов на работу. Начальный прогон имел один промах телефонного нажатия;
он не считается успешной проверкой.

Новая кнопка отдыха не должна сжимать весь телефонный HUD в высокие текстовые
колонки. При наличии отдыха показатели/погода/кошелёк используют один ограниченный
ряд, отдых с подсказкой — следующий. Погода представлена значком с доступным
названием и раскрываемой карточкой. Все суммы и объяснения остаются доступны.
