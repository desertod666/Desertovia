## Узкий допуск F001/F002

FarmerAdmissionEnabled — явный переход прав работы на общих грядках. По
умолчанию false для совместимости, владелец включает его явно; автоматической
смены правил/назначений при миграции нет. Это ещё не переключатель готовой
экономики урожая90/10. Полный договор и расчёт F004 должны быть доведены отдельно.

| Действие | Царь | Посадник с CanManageFarm | Остальные |
| --- | --- | --- | --- |
| Включить ограничение общих грядок назначенными фермерами | Да | Нет | Нет |
| Назначить/снять IsFarmer | Да | Да | Нет |
| Выдать CanManageFarm действующему посаднику | Да | Нет | Нет |
| Работать на общей грядке после включения допуска | Только действующим героем с IsFarmer | Только с IsFarmer | Только с IsFarmer |
| Работать на сохранённой своей личной ферме | По прежним правилам | По прежним правилам | По прежним правилам |

Посадничество само по себе не даёт фермерского управления. Снятие посадника
сбрасывает CanManageFarm. Назначение не даёт иных политических прав, не меняет
профессию/навыки/владение. Новый запрос после снятия допуска запрещён; принятая
работа завершается по сохранённым условиям. Новые tend-fields после перехода
запрещены, чтобы не оставлять абстрактный обход ручного выращивания.

PUT farm/admission и citizens/{id}/farm-access используют RequestId и
EconomyReceipt с actor/payload fingerprint, существующую транзакцию и PG-lock
мира. Повтор старого назначения не отменяет более позднее снятие; тот же id с
другими условиями отклоняется. Цель и управляющий проверяются внутри того же мира.
Событие назначения публикуется после commit. Миграция44 FarmerAdmission добавляет
три bool c false по умолчанию; посевы, деньги, прогресс и личные фермы не преобразует.

В интерфейсе царя появились допуск фермера, отдельное поручение посаднику и явное
включение ограничения. Управляющий видит только фермерское назначение; на общей
ферме неназначенный житель может осмотреть участок и получает объяснение запрета.
Сервер остаётся источником прав, скрытие кнопок не заменяет проверки API.

## Вклад и фонд

Приняты владельцем40/30/10/20: посадка/все нужные поливы/удобрение/сбор. Если
этап не происходил, нормируются остальные; несколько поливов делят30. Повтор
одного принятого труда не добавляет веса. FarmContributionRules.Allocate использует
точные рациональные веса и детерминированный остаток, сохраняя весь заданный фонд
даже для1 дробной единицы или long.MaxValue. Дробная единица —1/1_000_000;
это точность учёта права, а не дополнительная физическая Food.

Распределитель проверен как Domain-компонент. **Он пока не подключён к сохранению
участников/урожая или выдаче Food/денег.** Первая часть не обещает работающую90/10.
Следующий срез обязан сохранить полезные действия на конкретном посеве и отдельный
однократный итог сбора с реальным принятым/потерянным выходом.

Владелец выбрал: **до фактического сбора денег нет**. Погибший до сбора посев
не создаёт продукты или зарплату; неиспользованный обеспеченный фонд возвращается.
История труда остаётся. При сборе — один обеспеченный фонд и сразу защищённые10%
реальной Food,90% общине; зерно/лён общие. Реальные складские потери уменьшают
оба запаса пропорционально. Claim не дублирует еду и не обходит вместимость склада.
