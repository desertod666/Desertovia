# Бой и связанный данж1.0

Текущий срез T032: восстановление нового активного боя после остановки процесса.
Существующие DungeonRun, DungeonSimulation, DungeonHub, DungeonWorker и settlement
сохраняются как основа. Этот срез не завершает T030/T031/T032 и не меняет правила
новой группы или владения трофеями до ответа владельца.

## Сохранение и интеграция

- Миграция46 AddDungeonCheckpoints добавляет nullable jsonb DungeonRuns.CheckpointJson.
  Старые герои/вещи/посевы не переписываются. При Marching→Running начальный снимок
  фиксируется в той же транзакции, что и смена фазы.
- DungeonCheckpoint version1 хранит точные координаты, путь и очередь точек,
  цели, здоровье, стрелы, лечение, выход, cooldown, опыт, трофеи, этаж, время и исход.
  Карта и параметры врагов закреплены снимком. Округлённый transport snapshot
  не используется для восстановления. Изменение HeroClassCatalog/MonsterBrain
  требует проверки совместимости версии, а не молчаливого объявления вечной совместимости.
- DungeonRandom хранит состояние SplitMix64. Повтор продолжения не перебрасывает
  добычу; расчёт поломки при settlement также имеет устойчивый seed.
- LiveDungeon.Operation последовательно пропускает команды/тики одного боя.
  Изменения рассчитываются на отдельной копии и становятся видимыми только после
  commit. Hub подтверждает ручную команду после записи. Ревизия исключает чужую
  устаревшую запись; идентичный повтор после потерянного ответа commit не платит снова.
- Снимок выхода, награда, возвращённое снаряжение и финальная фаза фиксируются
  одной транзакцией с обычным хозяйственным журналом. Обычный тик/команда не
  меняет инвентарь и сохраняет только DungeonRun под теми же process/PG world locks,
  без полного пересчёта складов на каждом кадре.
- Worker ведёт максимум одну запись на бой; ожидание одного царства не блокирует
  другой бой. Время между успешными тиками учитывается с прежним пределом0,5с.
  Простой выключенного процесса не отнимает здоровье задним числом.

## Перезапуск и совместимость

Gathering/Marching продолжаются по сохранённым срокам. Новый Running со снимком
восстанавливается с теми же героями/владельцами/внешностью, включая уже вышедших.
Старый Running без снимка использует прежнее возвращение без награды: отсутствующую
память старого боя восстановить нельзя. Повреждённый/неподдерживаемый снимок
сохраняется для разбора и не заменяется новым боем; остальные корректные походы
восстанавливаются. Ended повторно не запускается.

Обычные старые in-memory тестовые/совместимые старты без Save сохраняют прежний
latency путь. Все новые реальные старты через AdvanceDungeonAsync получают Save.

## T031/T032 · Ручная сцена и выход из активного боя ·21.10

CombatRules.SelectAmbush отделяет прежний выбор встречи от мгновенного Fight,
сохраняя вероятность, ночной множитель, мирное время и порядок RNG в старом
Ambush. AmbushScene строит одну лесную сцену12×9 на60 секунд и одного героя
из его фактических навыков/оружия/стрел/брони. Она использует DungeonSimulation,
его команды, поиск пути, collision и точный checkpoint; второй боевой движок
не вводится. FoeDefinitions — закреплённые сервером параметры этой сцены,
старые карты используют прежний каталог. Числа первого среза ещё требуют
баланса. Сама сцена не выдаёт предметы или XP: награда должна пройти через
один результат принятой работы и её существующий фонд, а не второй loot table.
Ниже описано последующее подключение к принятой работе; исходные проверки
этого раздела относятся к предыдущему срезу сцены и отхода.

В действующем данже уже доступна команда DungeonHub.Retreat. Как MoveTo,
она проверяет владение героем/текущее лечение и фиксируется через LiveDungeon
и PostgreSQL до подтверждения. Герой идёт к входу с обычной скоростью, остаётся
Fighting и доступной целью до достижения выхода. Во время отхода не принимает
новую атаку/передвижение. Повтор приказа не сбрасывает путь. Падение на дороге
остаётся настоящим поражением; успешный выход не помечает героя раненым.
Далее работает прежний однократный возврат вещей/трофеев. Закрытие страницы
не заменяет эту команду и не удаляет героя. Отдых запрещён до выхода.
Правила новой группы/деления трофеев по-прежнему ожидают решения владельца.

RetreatRequested сохраняется в checkpoint как необязательное поле с default
false. Старые JSON без него и без FoeDefinitions загружаются. DTO даёт
retreating, личная кнопка и короткая подсказка объясняют уязвимость; после
подтверждённого снимка кнопка показывает «Отступаю…». Очередь dungeonOrders
пропускает команду через существующие поколения подключения и не повторяет
её после reconnect. Сначала читается доступный run, затем создаётся hub group.
Приватный допуск подключён следующим срезом и проверяется до вступления.

Проверки:637 Domain (9 новых случаев сцены/отхода/старого checkpoint),15 API
существующих данжей и checkpoint, включая обоих актёров, запрет отдыха,
принадлежность, rollback PostgreSQL и reload;21 client unit;12 browser
(6 retreat +6 control дороги), RU/EN и ПК/320px; TypeScript/Vite/oxlint.
На настоящем локальном UI тестовый житель отступил, сохранённый checkpoint
показал Left/RetreatRequested/ExternallyWithdrawn, DungeonRunId снят; до выхода
отдых отклонён, после — разрешён, кошелёк110 сохранён. Царь того же тестового
run также вышел через UI при завершении сценария. В подготовке сокращены
только Gathering/Marching deadlines своего synthetic run; состояние боя и
исходы не редактировались. Скрипт сначала проверил отсутствующее поле DTO;
итог подтверждён отдельным чтением реального checkpoint и API отдыха.
Целевую задержку/физический телефон эти проверки не подтверждают.

Контракт интеграции T031 (реализован в следующем локальном кандидате):

1. Сохранить выбор встречи один раз за принятую работу и версию её правил;
   незавершённые старые циклы завершаются по историческому контракту.
2. Записывать владельца/связанный цикл/seed/checkpoint приватного боя атомарно.
   Публичный общий DungeonRun и одновременные личные встречи не должны
   сталкиваться в запросах «один активный данж мира» или подписках.
3. Пока встреча активна, работа не завершается/не оплачивается; её фонд,
   материалы и начало сохраняются. Согласовать Start/Cancel/GoTo/Rest,
   settlement worker, внешнее лечение и активный raid admission.
4. Ручной исход превращается в один FightReport прежнего CycleEngine;
   успешный результат/рана/стрелы/износ и выплата проходят единую транзакцию.
   Повтор, падение commit и восстановление не выбирают врага заново и не
   начисляют вторую добычу или опыт. Новые потери багажа/смерть не включаются.
5. Личный DTO/карточка открывают собственную сцену с её названием и понятным
   возвратом. Нужен полный сценарий работа→встреча→исход→награда→отдых с
   disconnect/restart/конкуренцией, старым циклом и сохранностью имущества.

Это остаётся частичной T031, а не выполненными A13/A14/A17 или всей1.0.

При осмотре реального320px кадра исправлен приоритет статуса: Left показывается
как выход, даже когда сохранён RetreatRequested. Это включено в RU/EN browser
сценарии. В T035 остаётся видимый недостаток: карта данжа на высоком узком
экране мала, много вертикального пустого места. Нужны работа камеры/масштаба
и проверка нажатий; наличие44px кнопки не объявляет весь телефонный бой готовым.


## T031 · Принятая работа и приватная встреча ·21.10

Новые опасные работы получают версию1 и сохранённый seed в той же операции,
что принятие задания и обеспеченного фонда. Выбор врага выполняется один раз
после срока работы; старые циклы версии0 завершаются по прежним правилам.
Private run связан с жителем, заданием и исходным временем принятого цикла;
уникальный индекс запрещает вторую встречу того же цикла. При задержке внешнего
лечения связь сохраняется, даже если больница сдвинула срок работы.

GameService.Encounters использует существующие DungeonSimulation/LiveDungeon/
checkpoint, а CycleEngine ожидает исхода. Полный бой доступен только владельцу
аккаунта; он не подменяет публичный сбор царства. Публичное открытие и вариант
Всевышнего повторно проверяют занятость царя личным боем. Активный набег с тем
же актёром блокирует запуск личной сцены. Лечение/новая рана откладывают встречу.

Закрытие окна не завершает бой. Перейти к новой работе, отменить старую, уйти
или включить отдых в обход отступления нельзя. Заранее запрошенный отдых
вступает после исхода. Собственный DTO открывает сцену автоматически и даёт
ссылку возврата, если игрок вернулся на карту. На телефоне остаются команды
существующей сцены; окончательная приёмка камеры/нажатий T035 ещё впереди.

Итог превращается в один FightReport: прежние рана/износ/XP и только фактически
выпущенные стрелы. У сцены нет второй таблицы наград; производство и выплата
проходят через принятую работу и её существующий claim. Отступление не выдаёт
продукт или зарплату. Потеря commit откатывает checkpoint, вещи и расчёт фонда;
повтор того же результата не оплачивает работу снова. Новых правил смерти
или потери багажа этот срез не вводит.

Миграция51 добавляет поля и индекс без переписывания старых checkpoint.
В изолированной БД50→51 сравнены старые строки всех28 жителей, миров,
кошельков, экономики и DungeonRuns: хеши совпали после исключения только новых
полей. Откат схемы отказывается удалять принятые новые циклы/историю встреч;
для такого состояния нужен исходный backup и согласованное восстановление.
Это сравнение не объявляется проверкой всех остальных таблиц.

Реальный сценарий: synthetic hunt принят через API, его настоящее ожидание
не сокращалось; управляем только исходным seed выбора врага в своём fixture.
На320px сцена открылась автоматически. После backup/перезапуска API сохранились
run и принятый цикл, враг выбран нажатием на canvas, достигнута победа;
кошелёк110→120 один раз, затем Resting, ошибок страницы0. Параметры жителя
Strength10/Endurance10 допустимы для развитого героя; неуязвимость не включалась.

Локальные доказательства:644 Domain;17 разных API случаев (13+4: checkpoint,
приватность, фонд/исход, прежний цикл, лечение, реальный отказ final commit и
повтор, безопасный отказ Down);10 browser случаев RU/EN, ПК/320px; frontend
TypeScript/Vite/oxlint. После уточнения характеристик ветерана повторно прошли все7 WorkEncounter
API случаев; отдельный новый тест свежего каталога/повторной проверки занятости
царя прошёл. Всего18 разных локальных API случаев, не полный API набор. Полный CI текущего кандидата ещё не выполнен. Квитанция:
WORK_ENCOUNTERS_VERIFICATION_1_0.json. Весь A14, новая группа/добыча, снабжение,
баланс и физические телефоны остаются незавершёнными; публичного выпуска нет.
