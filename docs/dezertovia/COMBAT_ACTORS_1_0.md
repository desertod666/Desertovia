# Один герой в бою · T015/T031, частичный A14

21.10.2026. Продолжение общего плана после PR88, без публичного выпуска.
Должность не должна позволять создать второе тело, уйти из активного боя
через данж/работу/отдых или восстановить здоровье переключением роли.

## Изменение

`GameService.CombatActors` определяет героя по accountId царского бойца
и citizenId жителя этого аккаунта в данном царстве. У старых бойцов-жителей
AccountId может отсутствовать; это не делает их невидимыми для проверки.

- Открытие данжа и присоединение проверяют активного бойца рейда до
  изменения группы, работы или снаряжения. Переключать класс в сборе можно.
  Аккаунт царя не может ответить на свой же сбор вторым героем-жителем.
- Новые боевые приказы и лечение проверяют участие аккаунта в сборе/марше/
  текущем данже. Отступление остаётся доступным для разрешения старого
  пересечения. Приказы в разных незавершённых рейдах не создают два тела.
- Движение, продолжение пути и отдых учитывают обе формы героя. Общий
  `StartAsync` не начинает новую работу/исследование/стройку в активном бою.
  Подтверждение уже принятого requestId возвращает прежнюю работу без
  повторного расхода. Автоматическое завершение принятого труда сохраняется.
- Если у царя уже есть боец-житель, приказ управляет им с его текущими HP
  и координатами; новая царская фигура не создаётся. Лечение такого бойца
  использует его настоящие личные лекарства и общий запас по старым правилам.
- Автоматическое вступление в рейд учитывает аккаунты, занятые данжем.
  Уже активный старый боец не исчезает из-за обнаруженного пересечения.
  Перед выходом сбора занятые бойцы исключаются из марша; зарезервированное
  снаряжение возвращается. Царский боец рейда больше не выключается ради данжа.
- Всевышний повторно проверяет занятость царя при предложении и подтверждении.

Все записи проходят существующий WithVillageAsync и PostgreSQL advisory lock:
два одновременных запроса не принимают несовместимые участия. Новых таблиц,
колонок, миграций или переписывания старых checkpoint нет.

## Интерфейс

`battleActor.ts` используется в GamePage, HUD и BattleControls. Политический
режим царя не скрывает его старого бойца-жителя. GamePage берёт его ID из
ownCitizen, сохраняя отдельное представление царского меню. Показываются
настоящие HP и кнопки лечения/отступления; атлас не предлагает уйти из боя.
При старом дубликате сервер и клиент одинаково предпочитают активное тело,
затем царское. Сам дубликат не превращается в новый запас здоровья.

## Что остаётся в A14 и общем плане

В исходном срезе2999073 ещё оставались80 HP/8 урона царского бойца.
Последующий MORTAL_HEROES_RAID_1_0.md вводит общие характеристики/экипировку,
лечение и выбывание для новых рейдов, сохраняя старые объявления. Данж
пока использует старый профиль; весь A14 остаётся открытым. Этот срез устраняет
обход через второе тело, но **не закрывает A14 целиком**. Новая постоянная
смерть и потери рюкзака без отдельного решения не вводятся.

Группа с готовностью/трофеями, снабжение, осады, восстановление, самостоятельный
Всевышний, оформление, Dcoin/подписки и музыка остаются в полном DAG. Ферма
не возвращается в начало очереди. Вся1.0 ещё не готова.
