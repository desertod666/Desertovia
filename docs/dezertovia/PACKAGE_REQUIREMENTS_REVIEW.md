## Свежая проверка спорных участков кода

Game pinned `b9b4b32ef1a3a8c7821a72126ea84ab64fc41b09`, bot pinned
`76de289b00a99c8e40fb2c061beab6e7af216b5c`.

1. `CycleEngine.Keep` в private-output вызывает
   `PersonalInventory.Add(citizen, kind, kept, 0)`. Поэтому существование поля
   CostBasis ещё не доказывает перенос стоимости производственных входов.
   Нужны PKG-T020/DV1-01 перед настоящей данью.
2. `CycleSettlementWorker` принимает завершённые циклы независимо от присутствия.
   `CitizenPresence` хранит соединения/присутствие, но не отдельный безопасный
   Resting. Поиск в Citizen/GameService/GamePage/api не обнаружил готовой
   очереди хозяйственных работ 1+1. Очередь боевых команд данжа — иной контракт.
3. Сравнение source пакета `4bb125f` с текущим game main по `src/web/tests`
   пустое. Более новые коммиты game добавили документы фермы, а не новую
   реализацию безопасного отдыха, налогов или подписок.
4. Сравнение bot `8dbbc3a` с текущим checkout по путям модулей карты пакета
   также не показало изменений. Независимые newsroom-изменения в боте есть;
   это не повод заменять весь бот старым payload из пакета.
5. В раннем снимке source map найден неверный путь DbContext, уже исправлявшийся
   при подготовке пакета. Сверка текущего дерева подтверждает
   `src/Desertod.Infrastructure/Data/DesertodDbContext.cs`; ранний вариант
   `src/Desertod.Infrastructure/DesertodDbContext.cs` использовать нельзя.

Проверки выше — статическое чтение/сравнение Git. Runtime, миграции,
игровые/нагрузочные тесты и production-запросы не запускались.

## Различать два реестра решений

В пакете D100–D118 — самостоятельные ID, которые пересекаются с историческими
ID репозитория. В нашей сверке писать **PKG-D103** для решения о чуде,
**PKG-D102** для смерти/потерь, **PKG-D104** для группы. Репозиторные D-102
означает общую ферму, D-103 — это поручение анализа. Ни одно не заменяет другое.
Точно так же `PKG-Txxx`/`PKG-Axx` обозначают исходные задания/кейсы пакета.

## Фермерские расхождения, которые нельзя скрыть

- Текущий SHARED_FARM_PLAN выбранной моделью ставит общий резерв выше выдачи
  заработанных 10%. Облачное дополнение рекомендует сразу резервировать
  реальные 10%, чтобы долг не рос без срока. Это **разные политики**.
  Рекомендуемый проект 1.0 — защищённый натуральный резерв при сборе;
  до будущей реализации нужно явно выбрать его либо ограниченную отсрочку.
  Это не изменение склада или прав реальных игроков данным документом.
- Веса 40/30/10/20, две порции на active24h и рецепт компоста в дополнении
  считаются предложениями/параметрами для проверки, а не неизменными правилами.
- Оплата нынешнего Harvest через WorkPay создаёт хозяйственные монеты; это
  ещё не ограниченная выплата из казны. Будущая ферма должна резервировать
  один фонд PKG-T022/25; нельзя одновременно добавить новую оплату из фонда
  и сохранить автоматическую полную оплату старого канала.
- Растение растёт офлайн и при отдыхе работника. Герой не начинает новые
  посевы/уход, не получает XP за время. Погашение ранее заработанного вклада
  при чужом сборе — settlement существующего обязательства, не новая работа
  спящего героя; точная политика фиксируется вместе с PKG-D101.
- Базовый расчёт дополнения: 30 циклов/жителя, 2 сбора/грядку/сутки,
  25% запас мощности. Для 5/10/20 работников спрос 50/100/200 Food;
  репа с H=6 требует 2/4/8 ферм, капуста с H=36 — 1/1/2.
  Ранее подготовленные оценки при 12/24/48 циклах — другие сценарии,
  их нельзя выдавать за исправление или опровержение исходной таблицы.
