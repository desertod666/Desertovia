# M1: reconnect, права и безопасный отдых

20.10.2026. Это продолжение основного DAG, а не закрытие Дезертовии 1.0.
Решения владельца: [D-105](DECISIONS.md). Код не выпущен на публичный сервер.

## PKG-T013: соединение и команды

`hooks.ts` присоединяется к VillageHub **до** восстановительного HTTP-чтения.
При первоначальной загрузке дополнительное чтение закрывает интервал между
первым снимком и подпиской. `adoptVillageState` не принимает полный снимок с
более старым `snapshotAt`; существующие ревизии боёв продолжают объединяться.

DungeonOrders отделяет поколения очереди. Старое подтверждение/ошибка не
очищает и не запускает очередь следующего подключения. При reconnect/resume
команды приостановлены, старый heroId сброшен; JoinRun заново подтверждает героя.
Повторные обновления объединяются, ошибки join обработаны. Поздний ответ join
старого поколения не возвращает полномочия. Монотонный elapsed не позволяет
ответу JoinRun откатить живой dungeonSnapshot; terminal-кадр сохраняется.

Проверено 7 клиентскими unit и 10 Chromium browser проверками: desktop/phone,
настоящий разрыв WebSocket, поздний ответ, ошибка/восстановление, другая hero
identity, отсутствие replay. Экономические requestId/проверки payload и quote
этой работой не заменяются. Полная A17 также зависит от новых боевых/мировых
потоков T031–035; scoped транспортные проверки не объявляют весь DAG готовым.

назначении роли, без предположения о скорости планировщика.

## PKG-T012: явный серверный отдых

`RestState`: Active → RestRequested → Resting → Active. Это не CitizenStatus,
WorkState.Paused, idle или disconnect. Ранее принятая работа завершается по
обычным правилам, включая её единственную оплату; Settle переводит героя в
Resting. Новые циклы, отмена ожидающего завершения, движение и вступление в
бой/данж запрещены. Пробуждение не запускает старую работу и не выдаёт наград.
Ожидание отдыха можно отозвать явным пробуждением, не меняя принятую работу.

`PUT /api/villages/{slug}/me/rest` действует только на собственного героя.
Сначала проверяются активные бойцы/участники данжа. Текущий бой надо покинуть
реальным отступлением, из данжа вернуться либо выйти из сбора. Обрыв связи
не включает защиту. Resting исключён и из live admission, и из legacy raid victims.
Рост грядок, обычное восстановление энергии и ранее заработанные расчёты не
становятся новым производством/опытом отдыхающего героя.

Миграция `20261020174853_SafeRest`: четыре добавочных поля Citizen/Village,
старые записи получают Active, предметы/балансы/координаты не преобразуются.
DTO дополняются RestState/RestRequestedAt, старые клиенты совместимы.
Клиент показывает компактный отдых/пробуждение с подсказкой и серверным
статусом, блокирует новые работы, не пытается оптимистично включать иммунитет.

Проверено: 550 Domain (в том числе3 новых), 2 focused API с повтором,
конкурентным settlement независимых GameService, чтением из новых DB contexts,
двумя игровыми днями без нового XP/выплат и запретом midfight rest.
Телефон/две вкладки/reload проверяются отдельно; текущий результат — progress JSON.
Новая миграция применена только к синтетической dev-базе после pg_dump:
`/tmp/foundation-before-restart-20261020T175228Z.dump` в выделенном контейнере.

## Уточнение допуска после запроса отдыха

Если новая схватка началась во время принятой работы, RestRequested ещё не
даёт защиты. Свежая проверка бойца в транзакции settlement не позволяет
завершению работы удалить героя из боя. Отступление/лечение остаются доступны;
новое вступление запрещено. После фактического выхода или конца боя сервер
завершает переход, без повторной оплаты работы. Дополнительные Domain/API
регрессии проверяют этот порядок. M1_VERIFICATION фиксирует предыдущий
bc9bd81; данное исправление требует собственного CI.
